# 白名单、风险评分与 IP 跳变

出口检测回答“当前使用哪些 IP”，访问规则回答“这些 IP 是否允许使用”。两组设置互相独立：你可以只检测 HTTP 出口，再用白名单或风险分判断，也可以选择 `both`，要求 HTTP 和 STUN 两个出口都通过。

## 访问规则

| 规则 | 配置值 | 放行条件 |
|---|---|---|
| 固定 IP 白名单 | `whitelist` | 检测到的每个出口都在 IP/CIDR 白名单中 |
| 风险评分 | `risk` | 每个出口都有有效风险分，且均不超过阈值 |

默认仍为白名单模式。切换为风险评分模式后，白名单不参与放行判断，也不会覆盖高风险结果。反过来，白名单模式不查询风险分。

风险分使用 [stormzhang/ipcheck](https://github.com/stormzhang/ipcheck) 中相同的 [proxycheck.io v2 评分来源](https://proxycheck.io/api/)，范围为 0～100，分数越高风险越高。本项目独立实现评分接口，没有运行 `ipcheck` 的本地账号、Cookie、钥匙串或历史残留检查。

阈值默认是 50。只有**高于阈值**才拦截，例如阈值为 50 时，50 分通过，51 分拦截。评分缺失、格式无效、接口限流或查询失败时，均不放行，不将未知分数当成 0。

这个分数表示第三方服务对 IP 的评价，不是 Anthropic 的内部风控分。阈值由用户自行选择。

## 评分缓存

默认缓存 6 小时，可设置为 1 秒至 7 天。

- **按 IP 保存：** 同一个 IP 出现在 HTTP 与 STUN 两路时，只查询一次
- **每次重新判断：** 缓存保存分数和查询时间，不保存放行结论。修改阈值后，旧分数会立即按新阈值判断
- **过期重新查询：** 查询失败时不沿用已经过期的低分结果
- **短暂退避：** 查询失败后等待约 15 秒再重试，期间继续拦截，避免每轮检测都消耗请求额度
- **区分查询身份：** 切换 API Key 后不会复用另一个 Key 的评分缓存

缓存与跳变状态保存在配置目录下的 `admission-state.json`。各进程通过文件锁和原子写入共享状态，避免 CLI 与后台守护同时查询同一个 IP。

不填写 Key 时使用服务的公开接口，额度和返回结果受评分服务限制。需要 Key 时，可在启动进程的环境中设置 `CLAUDEGUARD_PROXYCHECK_API_KEY`。程序不会把 Key 写入缓存或提示文本。评分模式会把待查询的出口 IP 发送给 proxycheck.io。

## IP 跳变检测

“检测 IP 跳变”是一个独立开关，默认关闭。

开启后，第一次完整通过访问规则的出口会成为基准。之后只要同一路检测到不同 IP，就触发持续拦截，**即使新 IP 也在白名单中，或风险分低于阈值，也不会自动放行**。

例如：

1. 当前 HTTP 出口为 A，通过白名单检查后记为基准
2. HTTP 出口变为 B，触发跳变拦截
3. B 即使已在白名单中，仍然被拦截
4. 退出或重启守护，拦截状态继续保留。自动切回 A 也不会解除
5. 用户确认当前出口后，程序重新检测，并按当前白名单或风险阈值检查。全部通过才解除拦截并更新基准

HTTP 与 STUN 分别保存基准，HTTP=A、STUN=B 本身不算跳变。检测协议缺失或访问检查失败时，不会悄悄把当前 IP 更新为可信基准。切换检测模式时，新出现的一路会在完整检查通过后建立自己的基准。

确认操作会再次查询出口。如果再次检测的 IP 与用户刚确认的地址不同，会拒绝解除，要求重新检查。关闭跳变检测会停止应用这条规则，但不会删除历史基准和已触发的拦截记录，再次开启后仍需按情况确认。

这里的“跳变”指两次已观测结果之间的变化，包括休眠、重启或换网络后的变化，不按国家或地理距离判断。两次检测之间发生又恢复的短暂变化，轮询可能无法观测。

## macOS 设置

菜单栏新增以下设置：

- **访问规则：** 选择“固定 IP 白名单”或“按风险分阈值判断”
- **风险分阈值：** 设置超过多少分时拦截
- **评分缓存有效期：** 以秒为单位设置缓存时长
- **检测 IP 跳变：** 开启或关闭跳变检测
- **确认当前出口，解除跳变拦截：** 检查并信任当前出口

也可以使用命令行：

```bash
claudeguard set-access-mode risk
claudeguard set-risk-threshold 50
claudeguard set-risk-cache-ttl 21600
claudeguard detect-ip-change on
claudeguard status
```

确认当前出口：

```bash
claudeguard ack-ip-change
```

命令会先显示当前出口，输入 `yes` 后才继续确认。

## Windows 与 Linux 设置

中文设置窗口提供同样的规则、阈值、缓存和跳变开关。点击“检测出口”可查看评分和原因，点击“确认当前出口，解除跳变拦截”可执行确认。

Linux 命令示例：

```bash
claudeguard set access_mode risk
claudeguard set risk_threshold 50
claudeguard set risk_cache_ttl 21600
claudeguard set detect_ip_change true
claudeguard ack-ip-change
```

Windows 使用 [Windows/Linux 安装说明](windows-linux.md) 中的 Python 入口调用相同的子命令。

这些规则共用同一套判断代码。Windows/Linux 版仍通过启动检查和进程监控拦截，不会因此自动获得系统防火墙阻断能力。

## 配置示例

以下字段应合并进已有配置，保留其中的白名单、程序路径等设置：

```json
{
  "ip_check_mode": "http",
  "access_mode": "risk",
  "risk_threshold": 50,
  "risk_cache_ttl": 21600,
  "detect_ip_change": true
}
```

HTTP 查询服务、评分查询与 Claude 的实际出站线路仍需由代理规则正确配置。评分是查询某个明确 IP 的信息，不会替你确认 Claude 是否真的使用了这个 IP。
